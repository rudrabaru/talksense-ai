# TalkSense AI
# Slide Content Rules

---

# Purpose

This document defines the mandatory writing, formatting, and content standards for every PowerPoint slide.

Its purpose is to ensure the generated presentation is concise, visually balanced, academically appropriate, and fully compatible with the university template.

These rules apply to **every slide** generated for the final presentation.

---

# 1. Core Philosophy

Slides are **visual aids**, not documents.

The audience should understand the key idea within **10–15 seconds**, while the presenter explains the details verbally.

Always prioritize:

- Clarity
- Simplicity
- Visual communication
- Readability
- Logical flow

---

# 2. One Idea Per Slide

Every slide must communicate **one primary message**.

Avoid mixing unrelated topics.

Examples:

✔ Problem Definition

✔ System Architecture

✔ Technology Stack

✘ Problem + Solution + Architecture + Results

---

# 3. Slide Structure

Every slide should contain:

- One clear title
- One short objective
- Three to four bullet points
- One dominant visual
- Speaker notes
- Design notes

No slide should feel overcrowded.

---

# 4. Bullet Point Rules

Preferred:

3–4 bullets

Maximum:

5 bullets

Each bullet should contain:

8–15 words

Maximum:

18 words

Every bullet should communicate one idea only.

---

# 5. Writing Style

Use:

- Short sentences
- Strong nouns
- Active voice
- Professional language
- Technical precision

Examples:

✔ Real-time transcription using Faster-Whisper

✔ Modular FastAPI backend

✔ Live dashboard analytics

Avoid:

Long explanations

Marketing language

Conversational wording

---

# 6. Avoid Paragraphs

Slides must never contain paragraphs.

Instead of:

"Our backend was designed using FastAPI because it provides asynchronous support and improves scalability..."

Write:

- FastAPI backend
- Asynchronous request handling
- Scalable architecture
- Low-latency communication

---

# 7. Visual Balance

The slide should visually appear approximately:

40% text

60% visual

Whenever possible, replace text with:

- Diagrams
- Pipelines
- Architecture
- Screenshots
- Tables
- Infographics

---

# 8. One Primary Visual

Every technical slide should contain exactly one dominant visual.

Recommended visuals include:

- System Architecture
- Workflow Diagram
- Technology Stack
- Process Flow
- Dashboard Screenshot
- UI Screenshot
- Timeline
- Comparison Table

Avoid using multiple unrelated visuals on the same slide.

---

# 9. Icon Usage

Use icons only to reinforce understanding.

Preferred icons:

- Database
- Server
- AI
- Cloud
- Dashboard
- Microphone
- User
- Analytics

Icons should remain:

- Flat
- Monochrome
- Minimal

Avoid decorative icons.

---

# 10. Color Usage

Follow the university template.

Do not introduce new colors.

Use emphasis sparingly.

Highlight only:

- Important keywords
- Numbers
- Final outcomes

Never color entire paragraphs.

---

# 11. Typography

Keep hierarchy consistent.

Title

↓

Bullets

↓

Figure captions

↓

Footer

Do not mix multiple font styles.

---

# 12. Visual Hierarchy

The audience should naturally read:

Title

↓

Primary visual

↓

Bullets

↓

Supporting notes

The eye should never struggle to find the important information.

---

# 13. Content Density

Less is better.

If a slide feels crowded:

Merge bullets.

Convert text into a diagram.

Use icons.

Replace lists with tables.

Avoid shrinking the font.

---

# 14. Technical Slides

Technical slides should emphasize:

Architecture

Workflow

Pipeline

Modules

Data Flow

Avoid excessive implementation details.

The presenter should explain the technical depth verbally.

---

# 15. Screenshots

Only use screenshots that:

- Are clear
- High resolution
- Show meaningful information
- Fit naturally within the layout

Avoid screenshots with excessive whitespace or unreadable text.

---

# 16. Tables

Use tables only when comparison improves clarity.

Maximum:

4 columns

5 rows

Avoid dense tables.

---

# 17. Diagrams

Preferred diagram styles:

- Layered Architecture
- Process Flow
- Pipeline
- Block Diagram
- Timeline
- Technology Stack

Diagrams should be clean and minimal.

Avoid unnecessary arrows or decorations.

---

# 18. Speaker Notes

Speaker notes should:

- Expand the slide
- Explain the visual
- Provide transitions
- Mention important technical details

Do not repeat slide text word-for-word.

Target duration:

30–60 seconds per slide.

---

# 19. Design Notes

Every slide should include recommendations for:

- Icon placement
- Highlight boxes
- Callouts
- Animation order
- Visual emphasis

Animations should remain minimal.

Preferred:

- Fade
- Appear
- Wipe

---

# 20. Academic Tone

Maintain a formal academic style.

Preferred words:

- Designed
- Developed
- Implemented
- Integrated
- Validated
- Optimized
- Evaluated
- Verified

Avoid:

Amazing

Awesome

Groundbreaking

Revolutionary

Game-changing

---

# 21. Transition Between Slides

Each slide should naturally connect to the next.

Example flow:

Problem

↓

Motivation

↓

Solution

↓

Architecture

↓

Workflow

↓

Technology

↓

Implementation

↓

Results

↓

Timeline

↓

Future Scope

↓

References

Avoid abrupt topic changes.

---

# 22. Common Mistakes to Avoid

Never:

- Use paragraphs
- Exceed five bullets
- Use tiny fonts
- Add decorative graphics
- Overuse icons
- Repeat information
- Overcrowd slides
- Use inconsistent terminology
- Mix unrelated topics

---

# 23. Final Self-Review Before Generating Any Slide

For every slide, verify:

✓ One clear objective

✓ Three to four concise bullets

✓ Maximum fifteen words per bullet

✓ One dominant visual

✓ Proper whitespace

✓ Consistent template layout

✓ Academic language

✓ Technical accuracy

✓ No duplicated content

✓ Speaker notes included

✓ Design notes included

---

# 24. Final Rule

When in doubt:

Prefer **less text and a stronger visual**.

A clean slide with one powerful diagram is always better than a crowded slide filled with text.

The final presentation should look like it was prepared by an experienced technical consultant for an academic project defense—not generated by an AI.
